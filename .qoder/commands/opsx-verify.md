# /opsx-verify — 验证实现

## 触发条件

- 用户输入 `/opsx-verify <change-id>`
- 实现完成后，归档前的验证步骤
- 用户说"验证一下"

## 行为指南

### 1. 规范合规验证

对照 proposal.md 和 design.md 检查：
- 实现是否完整覆盖了验收标准？
- 技术方案是否按 design.md 执行？
- 是否有遗漏的功能点？

### 2. 测试验证

- 运行全部测试套件
- 确认新增测试覆盖核心逻辑和边界情况
- 确认没有已有测试被破坏（回归）

### 3. 代码质量审查

- 函数长度、嵌套深度
- 命名清晰度
- 是否有硬编码、未处理的错误

### 4. 输出

```
🔍 验证结果: <change-id>

📋 规范合规: ✅ 通过
  ✅ 验收标准 3/3 覆盖
  ✅ 技术方案一致

🧪 测试: ✅ 通过
  ✅ 单元测试: 15 通过, 0 失败
  ✅ 新增测试: 5 个（覆盖核心 + 边界）
  ✅ 回归测试: 10 通过

📐 代码质量: ⚠️  1 个建议
  ⚠️  [file.ts:L42] 函数偏长（35 行），建议拆分
  ✅ 命名清晰
  ✅ 错误处理完善

📊 总评: ✅ 可以归档
  输入 /opsx-archive <change-id> 归档变更
```

## 关联指令

- 验证通过 → `/opsx-archive`
- 验证不通过 → 修复后重新 `/opsx-verify`
