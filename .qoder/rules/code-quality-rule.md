# Code Quality Rule

## 规则类型: ALWAYS

## 描述

Agent 编写的所有代码必须符合项目质量标准。遵循 YAGNI、DRY 原则和通用编码规范。

## 规则

### 1. YAGNI (You Aren't Gonna Need It)

- 只实现当前需要的功能
- 不为"将来可能需要"做预留设计
- 删除未使用的代码和依赖
- 不过度抽象

### 2. DRY (Don't Repeat Yourself)

- 相同逻辑不重复出现
- 发现重复时提取为共享函数/组件
- 但不过早抽象 — 等到第三次重复再提取

### 3. 代码可读性

- 命名清晰表达意图
- 函数单一职责，长度不超过 30 行
- 避免深层嵌套（最多 3 层）
- 复杂逻辑添加注释

### 4. 错误处理

- 所有 I/O 操作必须有错误处理
- 错误信息清晰可行动
- 不吞掉异常

### 5. 安全

- 不硬编码密钥、令牌
- 用户输入必须验证和清理
- SQL/命令使用参数化，防止注入

### 6. 禁止行为

- ❌ 复制粘贴代码
- ❌ 提交包含 TODO/FIXME 而不创建跟踪任务
- ❌ 提交调试用的 console.log
- ❌ 提交注释掉的代码
- ❌ 过度设计（为未知的未来需求增加复杂度）
