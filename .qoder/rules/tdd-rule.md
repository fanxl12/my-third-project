# TDD Rule

## 规则类型: ALWAYS

## 描述

Agent 在所有编写实现代码的场景中，必须遵循测试驱动开发（TDD）流程。

## 规则

### 1. RED — 先写失败的测试

- 在编写任何实现代码之前，必须先写一个失败的测试
- 如果发现已有实现代码没有对应的测试，在添加新测试之前，先删除该实现代码
- 测试必须能够运行并产生预期的失败

### 2. GREEN — 最小实现

- 只写让测试通过的最少代码
- 不允许提前实现未来可能需要的功能（违反 YAGNI）
- 所有测试通过后立即停止编写代码

### 3. REFACTOR — 改进结构

- 只有在测试全部通过（GREEN 状态）时才重构
- 重构只改进代码结构，不改变外部行为
- 重构后必须保持所有测试通过

### 4. 禁止行为

- ❌ 先写实现代码后补测试
- ❌ 一次写多个测试而不逐步验证
- ❌ 跳过 RED 阶段（必须看到测试失败）
- ❌ 在测试通过前就重构
- ❌ 在 Refactor 阶段添加新功能
