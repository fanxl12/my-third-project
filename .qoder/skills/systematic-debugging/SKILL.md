# Systematic Debugging Skill

## 触发条件

- 测试失败
- 运行时错误
- 非预期行为
- 用户报告 bug

## 行为指南

### 四阶段调试流程

### Phase 1 — 复现

1. 精确复现 bug
2. 记录复现步骤
3. 确认 bug 的范围和影响

### Phase 2 — 诊断

1. 收集信息：错误消息、堆栈跟踪、日志
2. 形成假设：可能的原因
3. 验证假设：使用调试工具、添加日志
4. 定位根因：找到导致 bug 的具体代码行

### Phase 3 — 修复

1. 先写失败的测试来捕获 bug
2. 实现最小修复
3. 确认测试通过
4. 添加回归测试防止复发

### Phase 4 — 预防

1. 分析为什么这个 bug 没有被已有测试捕获
2. 补充缺失的测试覆盖
3. 考虑是否需要添加防御性代码

## 技能

### 根因追踪

不要停留在表面症状，持续追问"为什么"直到找到根本原因：

```
现象: 用户无法登录
↓ 为什么？
API 返回 500
↓ 为什么？
数据库连接超时
↓ 为什么？
连接池耗尽
↓ 为什么？
未释放连接的泄漏
→ 根因！
```

### 防御性编程

修复后，在适当位置添加：
- 输入验证
- 边界条件检查
- 合理的错误处理

### 条件等待

调试异步问题时：
- 使用正确的等待机制
- 避免 `sleep()` 式的硬等待
- 用条件变量或轮询等待特定状态
