# /opsx:explore — 探索 & 头脑风暴

## 触发条件

- 用户输入 `/opsx:explore`
- 用户说"我想做 X 但不确定怎么做"
- 任何需要先探索再动手的场景

## 行为指南

### 1. 理解上下文

收到 `/opsx:explore <topic>` 后：
1. 先阅读 `openspec/project.md` 了解项目技术栈和架构决策
2. 阅读 `openspec/specs/` 下已有的规范，了解当前系统状态
3. 研究 topic 相关的现有代码和模块

### 2. Socratic 式提问

通过提问澄清需求：
- 这个功能的目标用户是谁？
- 核心使用场景是什么？
- 成功的标准是什么？如何衡量？
- 有什么技术约束或偏好？

### 3. 方案对比

提出 2-3 个可行方案，分析：
- 复杂度
- 可维护性
- 与现有架构的契合度
- 风险

### 4. 推荐路径

推荐最优方案并说明原因，遵循 YAGNI — 选最简单的可行方案。

### 5. 输出

```
🔍 探索结果: [topic]

📋 当前状态:
  - 相关已有模块: [list]
  - 已有规范: [list]

💡 方案分析:
  A. [方案名] — [一句话]
     ✅ 优点: ...
     ⚠️  风险: ...
  
  B. [方案名] — [一句话]
     ✅ 优点: ...
     ⚠️  风险: ...

🏆 推荐: 方案 X，因为 ...

📝 下一步: 输入 /opsx:propose <change-id> 创建正式提案
```

## 关联技能

- 设计确认后 → `/opsx:propose`
- 本技能与 `brainstorming` 技能互补：explore 更侧重代码库探索，brainstorming 更侧重方案设计
